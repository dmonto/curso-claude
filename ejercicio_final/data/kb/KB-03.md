### KB-03 · WorkHub: diagnóstico HTTP 401, 403 y 500

| Campo | Valor |
| --- | --- |
| Versión | 1.0 |
| Sistema | WorkHub; Angular + Express + Claude |
| Audiencia | Empleado y soporte L1 del laboratorio |
| Naturaleza | Datos ficticios para simulación; no es una política real del cliente |

#### Objetivo

Localizar la capa que devuelve el fallo: interfaz, backend del asistente, servicio de tickets o recurso enlazado. Un 403 de SharePoint no significa necesariamente que Express devuelva 403. Conserva el origen de cada error y distingue hechos de hipótesis.

#### Diagnóstico por código

| Código | Interpretación inicial | Comprobación segura |
| --- | --- | --- |
| 401 | La petición no presenta una autenticación aceptada | Revisar sesión y configuración del token ficticio en el backend; no mostrar su valor |
| 403 | La operación ha sido rechazada por autorización o un control de acceso | Identificar operación y recurso, comprobar alcance autorizado; no elevar privilegios |
| 500 | Error interno en el componente que responde | Recoger trace_id y hora; derivar a mantenimiento con logs saneados |

Los intermediarios pueden transformar errores. No diagnostiques una dependencia concreta a partir del código mostrado por Angular sin evidencia del backend.

#### Procedimiento

1. Registra pantalla, acción, hora, código y mensaje visible. Distingue «abrir documento» de «enviar mensaje al asistente».
2. Comprueba `GET /health` en `http://127.0.0.1:3000`. Un resultado correcto prueba la salud declarada por ese endpoint, no todos los servicios externos.
3. Si falla el chat, conserva el `trace_id` devuelto. L1 consulta únicamente los registros autorizados de esa operación, con duración, herramienta y resultado; no copia conversaciones completas.
4. Para 401, valida la sesión según [KB-01](KB-01.md). En el mock, el backend resuelve la identidad desde el token de laboratorio; cambiar `userId` o `role` en el cuerpo no concede acceso.
5. Para un documento con 403 sigue [KB-02](KB-02.md). Para un ticket no visible aplica [KB-06](KB-06.md); no intentes otras identidades.
6. Para 500, permite una repetición de lectura si no hay riesgo de efectos. Si era una escritura o confirmación, consulta primero el resultado de la acción: una respuesta perdida no prueba que la operación no se ejecutara.

#### Ejemplo y escalado

Si Ana puede utilizar el chat y obtiene 403 al abrir un enlace de SharePoint, registra dos resultados separados. No reinicies Express para intentar reparar permisos del documento. Si falla el asistente al llamar a una dependencia MAF, utiliza [KB-04](KB-04.md).

Escala a mantenimiento WorkHub cuando un 500 se repita, no haya correlación suficiente o el fallo afecte a varias personas. Adjunta ruta sin secretos, código, hora, trace_id y pasos reproducibles. L1 no reinicia servicios, edita `.env`, aumenta permisos ni publica cambios durante este flujo. La preparación y confirmación de incidencias se rigen por [KB-05](KB-05.md) y KB-06.
