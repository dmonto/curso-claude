### KB-02 · SharePoint 403: permisos, sesión y enlaces

| Campo | Valor |
| --- | --- |
| Versión | 1.0 |
| Sistema | SharePoint y acceso desde WorkHub |
| Audiencia | Empleado y soporte L1 del laboratorio |
| Naturaleza | Datos ficticios para simulación; no es una política real del cliente |

#### Síntoma y posibles causas

Al abrir un documento desde WorkHub aparece HTTP 403 o «Acceso denegado». Las hipótesis incluyen cuenta u organización incorrectas, enlace desactualizado, alcance del enlace incompatible con la persona, permisos del sitio/biblioteca/documento o controles de acceso. El código por sí solo no identifica la causa. Teams operativo no acredita permisos de SharePoint.

#### Procedimiento seguro

1. Recoge hora, mensaje exacto, alcance y referencia del documento. Evita conservar parámetros de enlaces compartidos que puedan conceder acceso; guarda una referencia saneada del recurso.
2. Comprueba la cuenta y organización con [KB-01](KB-01.md).
3. Pide abrir el sitio mediante un favorito conocido del laboratorio y navegar hasta el documento, sin construir direcciones alternativas ni intentar eludir controles.
4. Compara el resultado del enlace de WorkHub y de la navegación directa. Si solo falla el primero, registra «posible enlace desactualizado o contexto distinto» y deriva al responsable del portal.
5. Comprueba si puedes abrir otro documento al que ya tengas acceso autorizado. Si falla solo uno, acota al recurso; si falla toda la biblioteca, registra ese alcance. No utilices la cuenta de otra persona para comparar.
6. Si el propietario del recurso puede revisar los permisos, solicita esa revisión por el canal aprobado. Una solicitud de acceso no equivale a acceso aprobado. El agente no concede permisos ni añade miembros a grupos.
7. Realiza como máximo una repetición controlada tras corregir una cuenta equivocada. Si persiste, prepara una incidencia con [KB-06](KB-06.md).

#### Matriz de decisión

| Resultado observado | Siguiente paso |
| --- | --- |
| Cuenta incorrecta | Repetir con la cuenta prevista; no alterar permisos |
| Directo funciona, enlace de WorkHub falla | Equipo WorkHub; incluir referencia saneada |
| Sitio accesible y documento denegado | Propietario de SharePoint para revisar autorización del recurso |
| Varios sitios y servicios fallan al iniciar sesión | Equipo de identidad según KB-01 |
| No hay evidencia suficiente | Mantener hipótesis abiertas y preparar ticket |

#### Ejemplo del caso Ana

A las 09:15 Ana comunica «SharePoint 403 desde WorkHub; Teams funciona». Aún no se sabe si el enlace directo funciona ni si tiene acceso concedido al documento. La respuesta inicial debe proponer las comprobaciones anteriores, citar KB-02 y ofrecer un borrador si no se resuelve. No afirmes que ha perdido permisos o que hay una caída general.

#### Escalado y límites

Escala si persiste con cuenta correcta y ruta conocida, si requiere una decisión de permisos o si afecta a varios recursos. Adjunta alcance, hora, resultado de cada ruta y correlación disponible. No adjuntes el documento confidencial ni un volcado de red con credenciales. No cierres el ticket ni prometas un plazo no confirmado. Consulta [KB-05](KB-05.md).
